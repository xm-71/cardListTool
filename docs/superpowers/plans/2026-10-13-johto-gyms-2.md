# Johto Gym Challenge, Part 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chuck, Jasmine, Pryce and Clair become real Johto Gym Leaders after Morty, completing the eight-leader Johto badge case.

**Architecture:** Four new Gym decks (card JSON, imported cards, card scripts) go into `GYM_DECKS`, exactly as in part 1. `gym.ts` gets four more `JOHTO_LEADERS` entries and loses `JOHTO_UPCOMING`; the existing region model, rewards and `GymChallenge` panel already handle them.

**Tech Stack:** TypeScript, React 19, vitest + Testing Library, Playwright; `@ptcg/cards` card scripts, `@ptcg/bots` fuzz and round-robin.

**Spec:** `docs/superpowers/specs/2026-10-13-johto-gyms-2-design.md` (builds on part 1's spec and plan: `2026-10-13-johto-gyms-1-design.md`, `…-1.md`; follow its card-scripting method and helpers: `assertGymDeck` in `packages/cards/test/helpers.ts`, `callForFamily`/`countHeads`/`searchDeck`/`energyOfType` in `src/scripts/util.ts`, scripts of 151 cards export `set = 'sv03.5'`).

## Global Constraints

- Gym-legal cards only (mark H or later, or any `sv03.5` card); 60 cards; ≤ 4 copies per name (basic Energy aside); ≤ 1 ACE SPEC. `assertGymDeck(deck)` checks all of it.
- **No engine changes.** A card that needs a hook or rule the engine lacks is left out and replaced by a playable card; record each omission as a `Ruling:` in the ledger.
- Bots: all four use `difficulty: 'hard'`. Badges and types (display): Chuck "Storm" Fighting, Jasmine "Mineral" Metal, Pryce "Glacier" Water, Clair "Rising" Dragon. Order: Chuck, Jasmine, Pryce, Clair, after Morty.
- Rewards come from part 1's `johtoBadgeReward(i)`: 250 / 275 / 300 / 325 credits and a `me02` pack. No change to rewards code.
- Round-robin target for each new deck: `[40, 60]` (Medium-piloted, 6 games per pair, both seats; Easy-piloted opponents); soften a deck (fewer evolution lines or Energy-acceleration, fewer copies of the best attacker) until it is in range.
- CLAUDE.md: every new Gym deck is added to `packages/bots` `test/gym-fuzz.test.ts` (count) and `scripts/round-robin.ts` (`GYM_TARGETS`); not to `DECKS`.
- Commands (repo root): `pnpm --filter @ptcg/cards exec vitest run <file>`, `pnpm --filter @ptcg/bots exec vitest run test/gym-fuzz.test.ts -t <id>`, `pnpm --filter @ptcg/web exec vitest run <file>`, `pnpm --filter @ptcg/cards import-cards` (network; then `pnpm exec prettier --write packages/cards/src/data/cards.json` and `git checkout packages/cards/src/sets.json` if prettier touched it).

## Review Focus

- A deck contains a card with no script (the bot's game would crash or silently misplay): `assertGymDeck` plus gym-fuzz for every new deck (Tasks 1–4).
- A save with 7 Johto badges: Clair is `next`, Chuck/Jasmine/Pryce are `beaten`; with 3 badges Chuck is `next` and Jasmine `locked` (Task 5).
- The Johto intro/“Badges: n / 8” text and tile count after `JOHTO_UPCOMING` is gone: no leftover "Coming soon" tile or "More leaders" sentence (Task 5).
- Four new portraits are distinct from all 17 existing ones (the portraits test) (Task 5).
- The economy `gym-decks` count and the bots gym-fuzz count match the number of decks (Tasks 1–5).
