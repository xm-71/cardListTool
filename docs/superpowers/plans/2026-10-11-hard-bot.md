# Hard Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Hard bot that also plays out the opponent's reply turn, thinks within a clock budget, and is offered in
the Duel picker.

**Architecture:** Medium's search helpers move into a shared `search.ts`. `hard.ts` reuses them and adds a reply
rollout and round-based sampling with a clock budget. The web app gains a `'hard'` difficulty that `botFor`, the Duel
picker and the credit table understand.

**Tech Stack:** TypeScript, vitest, pnpm workspaces (`@ptcg/bots`, `@ptcg/engine`, `@ptcg/economy`, `apps/web`),
React 19.

**Spec:** `docs/superpowers/specs/2026-10-11-hard-bot-design.md`

## Global Constraints

- Easy and Medium make the same choices for the same inputs as before this change.
- Hard defaults: `budgetMs` 1500, `minRounds` 1, `maxRounds` 16, `now` = `performance.now`.
- Acceptance (measured with the balance script and reported in the PR, not in CI): Hard wins ≥ 60% vs Medium across
  all starter, theme and meta decks, both seats; p95 think time ≤ 2 s per decision.
- The `Bot` type (`(view, legal, rng) => { action, rng }`) is unchanged.
- The Gym and Elite Four data keep their current difficulties.
- **Ruling (spec gap):** Hard Duel games pay credits like the other difficulties need to. Use `win.hard = 300` and
  `loss.hard = 70`, in line with Easy (100/30) and Medium (200/50).
- Run `pnpm check` before every push. Commits end with the session's attribution trailers.

## Review Focus

1. **A prompt opened during the opponent's reply rollout belongs to Hard's seat** (for example a promotion after a Knock
   Out): the rollout must answer it with Easy for that seat, not stop or throw. Covered by a Task 2 test.
2. **Only one legal action** (for example only `endTurn`): Hard returns it at once without searching. Covered by a
   Task 2 test.
3. **The game ends during Hard's own rollout:** the reply rollout is skipped and the result is scored as a win or loss.
   Covered by a Task 2 test.
4. **A budget already spent before round 1:** Hard still runs `minRounds` and returns a legal action. Covered by a
   Task 2 test.
5. **An engine error inside a guessed world:** that candidate scores `-1e9` in that world, and if everything throws Hard
   falls back to Easy (no crash in the worker). The fuzz run in Task 3 exercises this.

### Task 2: `createHardBot`

**Files:**
- Create: `packages/bots/src/hard.ts`, `packages/bots/test/hard.test.ts`
- Modify: `packages/bots/src/index.ts` (export `createHardBot`, `type HardOptions`)

**Interfaces:**
- Consumes: Task 1's `rolloutTurn`, `pickBest`, `dedupe`, `PROMOTE`, plus `determinize`, `evaluate` and
  `createEasyBot`.
- Produces:
  ```ts
  export interface HardOptions {
    budgetMs?: number;   // 1500
    minRounds?: number;  // 1
    maxRounds?: number;  // 16
    now?: () => number;  // performance.now
    /** Called after each finished round with its 1-based number (tests and timing only). */
    onRound?: (round: number) => void;
  }
  export function createHardBot(
    registry: CardRegistry,
    decks: [DeckList, DeckList],
    seat: PlayerId,
    options?: HardOptions,
  ): Bot;
  ```

**Behavior:**
- **Scoring one candidate in one guessed world:**
  1. Apply the action.
  2. Run `rolloutTurn` for Hard's seat.
  3. If there's no result and it is now the opponent's turn, play the reply with
     `rolloutTurn(engine, easy, state, opp, rng, 60)`. Prompts for either seat are answered by Easy, so the step loop
     uses the prompt's player, as `rolloutTurn` already does.
  4. Score with `evaluate(state, seat, registry)`.

  A candidate that throws scores `-1e9`.
- **Rounds:** each round makes one fresh `determinize` guess and scores every deduped candidate in it.
  - Record `start = now()` before the first round.
  - Stop after a round when `round >= maxRounds`, or when `round >= minRounds && now() - start >= budgetMs`.
  - Then call `pickBest`.
- **Promotions:** a `PROMOTE` slot prompt with more than one candidate is scored the same way. Promote the bench slot,
  as in Medium's `choosePromotion`, then play the reply rollout if it is the opponent's turn, then evaluate.
- **Shortcuts:** other prompts, and cases with at most one candidate, go straight to Easy. Any throw outside a single
  candidate's scoring falls back to Easy.

- [ ] **Step 1: Write the failing tests** in `hard.test.ts`. The KO-reply test uses a custom registry built with
  `miniRegistry` and `pokemon` from `@ptcg/engine/testing`:
  - **Cards:**
    - `tank`: `isEx: true`, hp 200, retreat cost 1, one attack costing 4 Colorless.
    - `spare`: hp 60, retreat cost 0.
    - `sniper`: one attack, cost `['Colorless']`, printed damage 0. Its script `{ attacks: { 0: { damage: () => 250 } } }`
      really deals 250, which `evaluate`'s threat check can't see.
  - **Position:** after setup and one `endTurn`, the side to act (`me`) has
    - `tank` Active with 1 `t-dark` attached,
    - `spare` on the Bench,
    - no Energy in hand.

    The opponent has `sniper` Active with 1 `t-dark` attached, and a `t-basic` on the Bench.
  - `test('Hard retreats an ex Pokémon the opponent can Knock Out next turn; Medium does not')`:
    - `createHardBot(reg, decks, me, { maxRounds: 2, now: () => 0 })` chooses `{ type: 'retreat', … }`.
    - `createMediumBot(reg, decks, me, 2)` chooses an action whose `type` isn't `'retreat'`. Same view, legal actions
      and rng 7.
  - `test('stops at maxRounds when the clock never moves')`: `now: () => 0`, `maxRounds: 3`. The `onRound` calls are
    `[1, 2, 3]`.
  - `test('stops after minRounds once the budget is spent')`: a clock that returns 0, then 10000 for every later call,
    with `minRounds: 2`, `budgetMs: 1500`. The `onRound` calls are `[1, 2]`.
  - `test('a budget spent before the first round still returns a legal action')`: the clock is always 1e9 after the
    first call. The returned action is in `legal`.
  - `test('same inputs and options give the same choice')`: call twice with `maxRounds: 2, now: () => 0`. Both results
    are equal with `toEqual`.
  - `test('returns the only legal action without searching')`: `legal = [{ type: 'endTurn' }]`. The result is that
    action, and `onRound` is never called.
  - `test('scores a game that ends in its own rollout without playing a reply')`: the opponent's Active has 10 HP left,
    it is their last Prize-relevant Pokémon with an empty Bench, and Hard's Active can attack. Hard chooses `attack`.
  - `test('answers a prompt for its own seat during the reply rollout')`: in the KO-reply position with `spare` removed
    from the Bench and a `t-basic` there instead, Hard's search returns a legal action without throwing (a promotion
    prompt for Hard's seat comes up in the reply).
